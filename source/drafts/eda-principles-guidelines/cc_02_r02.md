### EDA-R-02: Consumers are robust against duplicate events

| Strategy | Consumers are robust against duplicate events. |

#### Description

An event is a message that describes something factual that has already happened. Each event must include a **source** and an **ID** to uniquely identify it. The same event ID must be used when retrying delivery or sending the event through multiple channels. Consumers must treat events with the same **source** and **ID** as duplicates.

Being robust means that consumers must handle duplicates safely by ignoring them during processing. Deduplication is based on the **source** and **ID**, which are mandatory fields for all events. See [Event Data Specification id](https://hetnormo.github.io/API-standards/event-data-specs/#field-id).

#### Implication

*  With event deduplication, consumers prevent reprocessing by recording which events they have already handled. When storing the result of processing an event, the consumer must also record that the event was processed. If the same event arrives again, the consumer can check the record and skip it.
*  Producers must support this by ensuring the event ID remains the same for retries and multi-channel delivery. This allows consumers to reliably detect duplicates based on the event’s source and ID.
