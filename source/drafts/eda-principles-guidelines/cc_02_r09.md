### EDA-R-09: CloudEvents use structured mode

| Strategy | CloudEvents use structured mode. |

#### Description

CloudEvents must be transported using structured mode. In structured mode, the complete CloudEvent representation, including all CloudEvent context attributes and the optional data attribute, is contained within a single serialized event document.

Structured mode provides a consistent and self-contained event representation that is independent of transport-specific headers, properties, or metadata mechanisms. Consumers can process CloudEvents using a single parsing model without requiring knowledge of protocol-specific mappings.

Structured mode is the preferred representation for interoperability within the Dutch energy sector.

### Label

MUST

#### Rationale

*	EDA-P-12

#### Implication

*	Producers should publish CloudEvents as a complete structured event document
*	Consumers should be capable of parsing the full CloudEvent envelope from the event payload 
*	Structured mode simplifies interoperability between implementations by avoiding protocol-specific mappings of CloudEvent attributes
*	Binary mode must not be used for transporting CloudEvents, regardless of the underlying protocol
