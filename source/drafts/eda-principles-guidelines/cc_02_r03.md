### EDA-R-03: Queues are durable

| Strategy | Queues are durable. |

<details><summary>

Open section for explanation, rationale and exception conditions 

</summary>

#### Description

Durable message queues with persistent messages support guaranteed delivery: when the event broker receives a persistent message, it stores the message in memory for fast retrieval and also persists it to physical storage (such as a filesystem or database). If the event broker restarts, both the durable queue definition and the persistent messages are preserved on disk, ensuring they remain available for processing when the broker comes back online.

AMQP queues are durable unless there's a specific performance requirement or the data is ephemeral in nature. 

#### Label

MUST

#### Rationale

*	EDA-P-08

#### Implication

*	Default Configuration: Developers explicitly configure queues as durable when declaring them.
*	Documentation Requirements: Any non-durable queues must be justified and documented.
*	Monitoring: Need to monitor disk usage and queue persistence health.
*	Backup Strategy: Durable queues must be included in backup/recovery procedures
