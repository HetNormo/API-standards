### EDA-R-06: Consumers are configured with backpressure mechanisms

| Strategy | Consumers are configured with backpressure mechanisms. |

#### Description

AMQP consumers should configure appropriate backpressure mechanisms to control message flow and prevent system overload. The primary mechanism is the prefetch count configured via _basic.qos_, which limits the number of unacknowledged messages a consumer can receive at once.

Backpressure ensures consumers process messages at a sustainable rate based on their capacity, preventing message accumulation that could lead to memory exhaustion, processing delays, or system instability. 

Consumers should set _explicit prefetch limits_ rather than accepting unlimited message delivery. The prefetch count should be determined based on consumer processing capacity, message size, and workload characteristics (CPU-bound vs I/O-bound). Manual acknowledgments are required for prefetch-based flow control to function correctly.

#### Implication

*	Consumers must use manual acknowledgments (not auto-ack mode) in combination with prefetch limits.
*	Start with conservative prefetch values (1–10 messages) and adjust based on observed performance.
*	For CPU-bound tasks, set prefetch to 1-2× the number of worker threads. For I/O-bound tasks, higher values (10-50) may be appropriate depending on latency characteristics.
*	Monitor unacknowledged message counts, consumer processing latency, and throughput to validate prefetch configuration effectiveness.
*	Note: Effective backpressure also depends on broker flow control and queue capacity; prefetch alone does not fully guarantee system stability under extreme load.
