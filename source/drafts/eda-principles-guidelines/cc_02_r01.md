### EDA-R-01: Events are named as past-tense noun-verb compounds

| Strategy | Events are named as past-tense noun-verb compounds. |

<details><summary>

Open section for explanation, rationale and exception conditions 

</summary>

#### Description

An event represents a fact: something that has happened in the domain. To make this explicit, event names must use a noun-verb form in the past tense, which clearly signals that the occurrence is completed.

Use business-facing domain language (preferably based on NBility and expressed in CIM) rather than technical implementation details. Event names should be short and unambiguous. Nouns should not be abbreviated, and verbs should always be in simple past tense.

Examples:
   *	CustomerCreated
   * 	WorkActivityPlanned
   *	ConnectionUpdated

#### Implication

*   Event names should not encode implementation details (e.g., queue names, database table names, or transport metadata). Those belong to the technical layer, not the canonical event name.
*   Changing an event name is a breaking change for consumers; follow the versioning and deprecation policy when renaming events.
